# The Cloudflare R2 provider

Keeps your library in an R2 bucket, served by a Cloudflare Worker. There are no
access keys to create — it reuses whatever login wrangler already has.

## Setting it up

You'll need a Cloudflare account.

**1. Edit the two files that carry a deployment.** Both are checked in with this
project's own values, and both are meant to be changed:

| file | change |
| --- | --- |
| `bookshelf.config.json` | `storage.bucket` to your bucket name. Delete `storage.jurisdiction` unless you want EU data residency |
| `apps/bookshelf/wrangler.jsonc` | `name` to your Worker's name, and the `r2_buckets` entry to match your bucket |

They have to agree about which bucket holds the library. If they don't, the sync
tool stops and tells you before uploading anything your app wouldn't be able to
see.

**2. Log in, publish, deploy:**

```bash
npx wrangler login
npm run sync -- --create   # creates the bucket, then uploads to it
npm run deploy
```

## Configuration

```json
{
  "storage": {
    "provider": "r2",
    "bucket": "books",
    "jurisdiction": "eu",
    "worker": "apps/bookshelf"
  }
}
```

| key | what it does |
| --- | --- |
| `bucket` | your R2 bucket. Leave it out and it's read from the Worker's `wrangler.jsonc` |
| `jurisdiction` | data residency, e.g. `eu`. Omit for the default |
| `worker` | where wrangler runs, so it finds the right `wrangler.jsonc` |

## Testing locally

```bash
npm run sync -- --local   # publish to the local miniflare bucket
npm run dev               # or npm run preview
```

`npm run dev` and `npm run preview` read that local bucket, not your real one.

Local publishing runs one upload at a time. Each invocation boots a miniflare
runtime that locks the state file, so parallel writes fail.

## `--force` doesn't clear everything

Wrangler can only get, put and delete objects — it can't list a bucket. So
`--force` removes what the last catalog recorded rather than everything actually
in there.

In practice that's exact for a bucket only Bookshelf manages. If you've put
other things in that bucket, `--force` won't remove them. The sync tool tells
you which of the two it did.

If you need the bucket genuinely empty, clear it from the Cloudflare dashboard
and then publish.

## Troubleshooting

**Your shelf is empty after deploying.** Your config and your `wrangler.jsonc`
probably name different buckets, or you deployed before publishing. Run
`npm run sync` and check which bucket it reports uploading to.

**`no binding named BOOKS`.** The Worker has no R2 binding. Check the
`r2_buckets` entry in `apps/bookshelf/wrangler.jsonc`.

**You want your shelf off the public internet.** `workers_dev` is `false` in
`wrangler.jsonc`, so your Worker has no `*.workers.dev` URL by default. If you
turn it on, remember there's no authentication — anyone with the URL can
download your whole library.
